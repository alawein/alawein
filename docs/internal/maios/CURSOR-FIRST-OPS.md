# Cursor-first ops (default plane)

Default execution plane for MAIOS after 2026-09-14. Multi-step and
mechanical work runs in Cursor (IDE or Cloud). Grok keepers stay thin
triage only. Cheapest adequate model wins.

Not a fifth keeper. Not a sync daemon. Not SoR for FLEET-BOARD (Policy
sole-writes that file). Grok chat underlying model is not SoR-controlled.

## Default plane

| Work | Plane | Stop |
|---|---|---|
| Orient / Approve / one nudge | InlineGrok | Executors, panels, long folds |
| Code / PR / tests / docs-in-git | Cursor | Asking Grok to re-run the same job |
| Grill / architecture opinion | OpenRouterPanel lite | Grok re-reading raw dumps |
| Fleet Job B short | InlineGrok | Job A full scan as the default |
| Fleet Job A/B long | Cursor | Five parallel Grok executors |

Under FREEZE (see `GROK-USAGE-FREEZE.md`), Job B > Job A. Ban
poll-as-daemon. Wake, webhook, or Meshal `Continue` only.

## Operator verbs

- `Offload: <task>`
- `Cursor: <owner/name> <ask>`
- `Panel: <question>` (lite 5)
- `Panel fleet: <question>` (7, rare)
- `Force Grok: <task>` (freeze escape hatch)

## Cost rule

Mechanical work uses Cursor or flash. Grill uses lite. Fleet is rare.
Grok cheap means behavioral short turns with no executors.

Scheme A keepers only: Intake, Policy, Cleanup, Editorial. BLOCK fifth
keeper. No bot named MAIOS. Do not invent a spend-optimizer bot.
